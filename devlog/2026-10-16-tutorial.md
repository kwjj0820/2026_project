# 2026-10-16 — 첫 튜토리얼

## 요청과 범위

사용자가 제안한 정보 수집·연결·활용 중심 튜토리얼을 구현하고 개발 내용을 문서화한다. 여관 아침, 길드 의뢰, 배송 착오 조사, 두 연결, 근거 제시, 회수·보고·취침까지를 대상으로 한다. 삭제와 적대 조우는 후속 범위다.

## 구현한 변경

- 평범한 검과 짐을 가진 모험가로 시작. 딸과 아침 대화·식사·부탁.
- 길드 등록증 조사, 의뢰 수락, 주문서 사본으로 누락 경로 보완.
- 여섯 기록과 두 활용 수단. 출처/정보 종류 표시, 둘 선택/연결, 수단 첨부/제시.
- 조사 순서 변경, 틀린 조합, 잘못된 상대 제시, 근거 없는 회수를 처리.
- 결과 보고·식사 선택에 따른 짧은 반응·취침·완료 화면.
- 런타임 전용 텍스트 UI와 동적 한국어 폰트, 스크롤, 자유 입력.
- 선택적으로 켜는 실제 AI 대화. 구조화 출력에서 현재 합법 행동만 적용.
- 요청 대기/중복 잠금, 입력 유지 재시도, 타임아웃, 오류 콜백, 응답 검증.
- 기존 API 요청 직렬화 보강, 키/전체 실패 응답을 로그에 남기지 않음.
- 튜토리얼 전용 저장/백업, 복원, 손상 시 잠금과 명시적 새 시작.
- 기존 AI/1막 모드와 저장 파일 유지. 신규 모드는 SampleScene에서 기본 활성화.
- 코어/테스트 어셈블리, NUnit 테스트, 독립 실행 도구, 새 `.meta` 제공.

## 검증 기록

- 독립 NUnit 실행: `Tools/Test-Tutorial.ps1`. 코어·저장·AI 응답 파싱 검증.
- 회귀 검사: `Tools/Test-ActOne.ps1`. 기존 초안의 두 돌파 경로와 56개 도달 상태.
- 스크립트 컴파일: Unity 내장 Mono 및 프로젝트의 UnityEngine/UI/TMP/Newtonsoft DLL로 검증.
- Unity EditMode 실행 시도: `Logs/tutorial-unity.log`. 프로젝트 경로 변경 직후 내부 종료 코드1로 끝났고 결과 XML이 생성되지 않았다. 이는 Unity 테스트 통과가 아니다.
- 실제 AI 요청은 실행하지 않았다. 사용자의 API 비용을 발생시키지 않는 코어 검증을 먼저 수행했다.
- 에디터 내 시각 배치·입력 포커스·한국어 입력·실제 네트워크 반응은 수동 확인이 남아 있다.

최종 실행 개수와 컴파일 결과는 아래 검증 완료 항목에 기록한다.

## 검증 완료

- 독립 NUnit: **27개 전체 통과**. 선택 순서, 수집/연결/제시 제한, 반복 효과 방지, 취침 조건, 저장/백업/손상, AI 출력 검증 포함.
- 기존 1막 회귀 검사: **56개 도달 상태 탐색 통과**.
- 새 코어를 별도 DLL로 빌드한 뒤 기존 스크립트에서 참조하는 컴파일 성공. 어셈블리 경계도 독립 확인했다.
- UnityEngine/UI/TMP/Newtonsoft를 참조한 에디터 스크립트 컴파일 성공. 플레이어 스크립트 컴파일도 확인했다. 이는 Unity Build Profiles로 완성 실행 파일을 만든 결과는 아니다.
- `git diff --check`로 공백/패치 오류를 확인했다. 한국어 UI·실제 입력·실제 AI 응답은 앞의 수동 검증 항목으로 남긴다.

## 후속 가독성 보정

- 사용자 피드백: 밝은 글자에 흰 바탕이 생겨 읽기 어렵다.
- `TutorialView`에서 버튼·입력·토글의 모든 Selectable 상태색을 명시적 다크 테마로 통일했다.
- 본문/입력 안내의 대비, 입력 캐럿 및 선택 영역 색상을 조정했다.
- 변경 후 전체 스크립트 독립 컴파일 통과.
- 화면 캡처 없이 확인한 상태색 보정으로, 실제 화면에서 글자 자체의 흰 사각형이 남는 경우 폰트/머티리얼 확인이 필요하다.
- 폰트 점검에서 기존 SDF의 sourceFontFile 참조 없음, padding 0을 확인했다. TTF를 직접 연결해 SDFAA/padding9로 생성하고 텍스트별 fontSharedMaterial을 명시하도록 보완했다. 기존 폰트 에셋은 수정하지 않는다. 화면 증상과의 인과는 실제 재생으로 추가 확인한다.
