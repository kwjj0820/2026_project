# 진행 상태와 표시 장면 분리

## 구현
- `GameState`: 코드가 관리하는 회차, 현재 사건, 회차 상태, 영구 기억.
- `LoopState`: 장소, 이번 회차 플래그, 관계 수치.
- `PersistentMemory`: 단서 ID, 지식 ID, 추적자별 기억.
- `DiscoverClue`: 중복 단서 획득 방지.
- `BeginNextLoop`: 회차 증가 및 임시 상태 초기화; 영구 기억 유지.
- `SaveData` v2: 게임 상태, 마지막 표시 장면, 대화 기록을 함께 저장.
- 기존 v1의 회차와 마지막 assistant 장면을 읽기 시 변환.
- 임시 파일 작성 후 교체, 이전 저장 백업, 손상 시 백업 복구.
- AI 요청에 구조화된 상태를 전달; AI 출력의 회차 번호는 코드 값으로 교정.

## 범위와 다음 작업
기존 Inspector 연결과 SceneDirective 화면 모듈을 유지한다.
currentEventId는 현재 시작 사건 ID만 가진다. 실제 사건 전환과 사망은 아직 연결하지 않았다.
AI 대사에서 단서나 죽음을 추측하여 상태를 변경하지 않는다.
다음 구현: ID 기반 선택지와 고정 사건 정의, 조건 판정, 결과 적용, 사망 후 루프 전환.
그 다음: 요청 중 중복 입력 방지 및 실패 처리, GameFlowController로 진행 책임 이동.

## 검증
Unity 내장 Mono와 Newtonsoft.Json으로 실제 상태/저장 코드를 컴파일해 독립 검증했다.
단서 중복 방지, 임시 상태 초기화, 영구 기억 유지, v1 변환,
JSON 왕복, 파일 저장/복원, 손상 시 백업 복구, 미래 저장 버전 거부를 확인했다.
검증은 별도 테스트 저장 폴더를 사용하며 실제 플레이 저장 파일을 변경하지 않는다.
